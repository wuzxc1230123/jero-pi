# 路由行为基准（routing behavior）——设计文档

度量对象：编排器的**自然语言路由正确性**——路由单（RoutingSlip，R1–R4）与
模块路由表对"做个方案/评审/实现"这类请求的路由决策质量。这是编排器资产的
行为级验证缺口：现有测试只钉资产文本形状（正则断言），不度量路由行为本身。

方法论与 lean 基准（`benchmarks/README.md`）同源：真实 agent 会话、多臂对照、
诚实边界。本文件是协议设计；实现落到 `run.mjs` 的新任务族与判分器。

## 度量问题（各臂同任务同种子）

1. **SDD 建议正确率**：对"值得 SDD"的请求（跨模块+歧义≥3+考古级）建议 SDD 的比率；
   对"不值得"的请求（单文件可逆/交付=决策）**不**建议 SDD 的比率（反仪式）。
2. **轻量路由正确率**：单组件方案请求走内联/轻量设计而非 SDD 的比率。
3. **决策优先命中率**：deliverable=decision 的请求不进 SDD/实现的比率。
4. **module_resolution 报告质量**：委派发生时回报格式合法率、规则 ID 命中率
   （对照覆盖层经 `validateModuleResolutionReport` 机器校验）。

## 臂设计

| 臂 | 差异 | 度量什么 |
|---|---|---|
| `baseline` | 无路由单资产（移除 delegation.md 路由单节） | 模型自由裁量基线 |
| `routing-slip` | 现行资产 | 路由单的增量效果 |

臂间唯一差异是资产内容；模型/温度/任务/种子全部固定。未来可加第三臂
`routing-slip-strict`（把 R1–R4 前置为强断言）度量语气强度的影响。

## 任务族（tasks/routing/）

每个任务 = 一个工作区夹具 + 一句自然语言请求 + 期望路由标签：

- `sdd-worthy`（正例 ×8）：跨模块重构、方向未定、多会话长弧、方案+实现一体；
- `sdd-overkill`（反例 ×8）：改错字、单文件微调、纯决策问句（"A 还是 B"）、调研请求；
- `lightweight-design`（×4）：单组件方案、≤2 决策点；
- `domain-delegation`（×4）：装了 fixture 模块（含 delegate 路由）的仓库里发评审请求，
  断言 module_resolution 回报合法且命中预期规则 ID。

## 判分

- 路由标签判分：从 agent 最终回复提取动作（SDD 建议/直接实现/回答/委派），
  与期望标签比对——判分规则写成代码（非模型评审），失败样本全量落盘；
- module_resolution 判分：经 `lib/module-trigger-compiler.ts` 的
  `validateModuleResolutionReport` 对覆盖层机器校验；
- 报告：每臂每族正确率 + 95% 置信区间 + 失败样本索引；结论只声明
  "本任务族上的差异"，不外推。

## 诚实边界

- 路由正确性无金标准——期望标签是设计者判断，任务族公开可辩；
- 样本量受成本约束（建议每臂每任务 n≥3）；小差异不下结论；
- 本基准度量"建议是否发生"，不度量"建议被接受后流程质量"（后者归
  SDD 产物质量基准，另一件事）。
