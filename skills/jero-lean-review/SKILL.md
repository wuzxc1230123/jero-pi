# Jero 精益评审（Lean Review）

评审一段 diff 的唯一问题：这里有多少代码是不必要的。只报告，不修改。

## 范围

- 默认只评审当前 diff（未提交变更或指定提交区间）。用户要求全库审计时，扫描整个源码树，按“可削减行数从大到小”排序输出。
- **明确越界**：正确性 bug、安全漏洞、性能问题不在本评审范围内——那是 `jero_review` 评审权威与常规评审视角（review-risk / review-reliability / review-resilience）的职责。
- **保护检查**：单个冒烟测试或断言自检是精益纪律的最低要求，不是膨胀，永不标记删除。

## 输出格式

每个发现一行：

```text
<file>:<line>: <标签> <是什么>. <用什么替代>.
```

标签词汇（与梯子横档对应）：

- `delete:` 整块可删——投机性需求、未被要求的抽象、为“以后”准备的样板。
- `stdlib:` 标准库已有——自写的解析、校验、工具函数。
- `native:` 平台原生能力已覆盖——自建组件、自写样式逻辑、应用层约束。
- `yagni:` 为不存在的需求而写——单实现接口、单产品工厂、常量配置、可选扩展点。
- `shrink:` 保留但可大幅缩短——可合并的重复分支、可折叠的层层包装。

## 计分

以唯一有意义的指标收尾：

```text
net: -<N> lines possible.
```

没有发现时：

```text
Lean already. Ship.
```

全库审计以 `net: -<N> lines, -<M> deps possible.` 收尾。

## 独立性

本技能是一次性的只读检查，与 `jero_review` 评审权威完全独立：不发起 START，不消耗捕获槽位，不改变任何评审状态，不做提交/推送/PR。它补充而非替代运行时动态提供的评审视角。
