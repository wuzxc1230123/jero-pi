# Jero 精益纪律（Lean Discipline）

最好的代码是你永远不用写的代码。本技能是精益纪律的完整参考；运行时注入的 lean 指令块（见模式一节）是权威的强度档位，本技能提供细则与示例。

## 梯子（Ladder）

在理解问题之后、写出代码之前，停在第一个成立的横档上。懒于方案，绝不懒于阅读：先读要改动的代码、追踪真实流程，再选横档。

1. **这真的需要存在吗？** 投机性需求直接跳过，并用一行说明。（YAGNI）
2. **代码库里已经有吗？** 近在咫尺的助手、工具函数、类型或模式——复用它。先找再写；重复实现几步之外已有的东西是最常见的浪费。
3. **标准库能做到吗？** 用它。
4. **平台原生能力够吗？** 原生 `<input type="date">` 优于日期选择器组件，CSS 优于 JS，数据库约束优于应用层代码。
5. **已安装的依赖能解决吗？** 用它。几行代码能解决的事，绝不新增依赖。
6. **能写成一行吗？** 一行。
7. **只有此时：** 写出能工作的最小实现。

## 规则

- 不加未被要求的抽象：单实现的接口、只有一个产品的工厂、为常量做的配置，都是多余。
- 不为“以后”写样板代码。
- 删除优先于新增；平淡优于取巧。
- 文件最少，能工作的 diff 最短。
- Bug 修复 = 根因，不是症状。改一个共享函数里的一处守卫，小于在每个调用点各补一个守卫；动手前先 grep 所有调用方。
- 输出预算：先代码，随后至多三行说明——跳过了什么、何时该补上（形如 `skipped: X, add when Y.`）。解释比代码长就删解释（用户明确要求的解释除外）。

## 懒惰边界（绝不简化掉的东西）

- 信任边界的输入校验。
- 防止数据丢失的错误处理。
- 安全措施。
- 可访问性基础。
- 用户明确要求的内容。用户坚持要完整版本时照做，不再重新争论。

非平凡逻辑必须留下一个可运行检查（断言自检或一个小测试）。YAGNI 约束测试的数量，绝不约束质量门。

## `jero:` 标记约定

有意的妥协——切掉了真实一角、有已知天花板的（全局锁、O(n²) 扫描、朴素启发式）——必须留注释标记，写明天花板与升级路径：

```ts
// jero: 全局锁，吞吐量成为瓶颈时改按账户分锁. ceiling: 单进程串行. upgrade: 并发写冲突出现时.
```

没有 `upgrade:` 触发条件的标记会被 `/jero:debt` 记为 no-trigger——那些是会悄悄烂掉的债。

## 模式（Modes）

运行时经 `/jero:lean <mode>` 切换，会话内立即生效；说 "stop lean"（或 `/jero:lean off`）关闭。

| 档位 | 行为 |
|---|---|
| `off` | 不注入任何精益指令，行为与本包历史版本一致。 |
| `lite` | 按请求完整实现，不做额外删减；但用一行点名更精简的替代方案。 |
| `full` | 默认档。梯子强制执行；规则与懒惰边界全部生效。 |
| `ultra` | YAGNI 极端主义：删除优先于新增；先交付最小实现，并在同一回合质疑需求的其余部分。 |

## 与 jero-pi 其余体系的关系

- **与 400 行评审预算正交**：预算管工作切片（chained PR、评审负载），梯子管代码本身的必要性。绝不为行数删除注释、测试或文档——“预算不是代码高尔夫”。
- **与评审权威独立**：本技能不发起、不选择、不重试任何 `jero_review` 生命周期操作；危险命令安全保持独立且权威。
- 分工：`jero-lean-review` 评审一段 diff 能删什么（只报告，不修改）；`jero-debt` 收割全库的 `jero:` 标记形成债务台账。
