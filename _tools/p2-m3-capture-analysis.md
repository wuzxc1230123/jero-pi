## B. Submission binding — descriptor math

Wire form (status/v5+ singular): `submission = {operation_token, argument_tokens[], value:{slot, domain, schema?, minimum?, maximum?, substitution_location}}`; legacy: `values[]` rows `{slot, domain, substitution_location}` (decoder :1423-1488). Normalized typed form: `ReviewCaptureSubmissionV1 {operationToken, argumentTokens, values[]}` (:435-439).

- **operation_token**: verb after `review` — `capture-result`, `capture-correction-plan`; `status` for the v6 untracked-selection form (:1425-1445). The relay composes `["review", operationToken, ...tokens]` (review-host-relay.ts:639).
- **argument_tokens**: the collect input's binding tokens MINUS host-only `--agent`/`--materialize` PLUS one value token `--input={{value}}` (fixture: submission argument_tokens 7 = arguments 9 − 2 host tokens; routing test recomputes exactly this, GP\tests\review-host-relay-routing.test.ts:98-99).
- **Domains** (closed per slot, decoder :1439/:1466-1467 + fixture): `artifact_path_or_stdin` (capture-result: a 0o600 staged file path or stdin bytes), `schema_bound_json` (untracked selection: canonical-JSON validated against the named schema), numeric 1..200 via `minimum`/`maximum` (correction_lines).
- **substitution_location**: index into argument_tokens; the referenced token MUST contain `{{value}}` (relay resolution review-host-relay.ts:261-280: exactly one value, safe-integer location in range, slot present — else typed SUBMISSION_CONTRACT_MISMATCH, never a synthesized form).
- **Materialization discipline**: reviewer RESULT bytes → tempfile `result.raw` (mode 0o600) inside a 0o700 `mkdtemp` staging dir, substituted into the {{value}} slot, staging removed after submit (:625-634, 671-683); bytes written BOM-less, byte-for-byte. PROMPT bytes never touch a file — they go to pi stdin verbatim (adapter `child.stdin.end(prompt)`, opaque-pi-reviewer-adapter.ts:187). Native client used the same discipline (`result.json` 0o600, native-review-cli.ts:2399-2404).
- **Snapshot discipline** (keep, extend): `snapshotReviewHostRelayRequest` deep-freezes tokens/values/environment BEFORE the first async boundary (:485-508); prepared result bytes live in a private WeakMap, never on the object (:323, :593); mutating them post-prepare is observable-fail (test :359-399). Test "preparation snapshots mutable submission tokens and values before materialization" must stay green after M3 rewiring.

## G. Staged projection + untracked content adoption

- **Upstream semantics**: `projection ∈ {workspace, staged}` (REVIEW_PROJECTION, review-integration-v2.ts:35-39); NativeStartRequest carries it (:578) with default workspace. Staged = freeze the candidate from the Git INDEX (what is about to be committed), not the worktree. M2 refuses it (status.ts:113-115 invalid-request; start.ts:43 comment "staged lands with the M3 capture renderer").
- **Workspace-drift problem** (the M2 review's test-infrastructure note): after a materialized correction edits the worktree, a fresh STATUS re-freezes the LIVE workspace and derives a new identity, so mid-correction STATUS drifts to `unrelated` (or pre-F7 mixed frozen blocks). Upstream never has this bug because at every evidence-pending sub-state the collect slot renders the identity native demands — for a correction that is the **fix-diff `--target`, not the live workspace snapshot** (native-review-cli.ts:2534-2540), i.e. the binding is lineage-bound.
- **Recommendation — lineage-bound projection** (do this as the drift fix): STATUS with an explicit `lineageId` (and the auto-match pass for lineages in correction-phase states `fix_required|fixing|fix_validating|ready_final_verification|final_verifying`) must NOT re-derive identity from the mutable workspace. Match the lineage first, then compute the live correction view as `initial_review_tree..worktree` (fix-diff kind, `deriveJeroCorrectionLinesV1` seam, snapshots.ts:399) and compare against the recorded fix application; the `frozen` block ALWAYS comes from the record, never the live manifest. Tree-only staging does NOT fix drift (a staged freeze drifts equally when the index moves) — it is an orthogonal START scope option.
