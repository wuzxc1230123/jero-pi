# UI 原型（同路由多变体）

在同一真实页面里生成 **3 个（至多 5 个）结构迥异**的变体，浮动条切换；用户翻着选，或各取部件（"B 的头部 + C 的侧栏"往往才是真答案）。

## 两种落位（强烈优先 A）

- **A：挂在既有页面**（默认）。路由已存在；变体渲染在同一路由，`?variant=` 搜索参数门控；既有取数、参数、鉴权全保留，只换渲染子树。原型是尚无页面的新区块/新卡片/新步骤时，也找宿主页面挂进去——真实头部、真实侧栏、真实数据密度里的变体才好评判，孤立抛弃页里每个变体看着都行。
- **B：全新抛弃路由**（仅当真无家可归，如全新顶层界面）。遵循项目既有路由约定，路径/文件名带 `prototype` 字样。动手前自问：真的嵌不进任何既有页面吗？

## 变体纪律

- **结构必须迥异**：布局、信息层级、主操作各不同。只换配色/文案是改版，不是原型；两稿撞形就带显式约束（如"禁用卡片网格"）重做一稿。
- 遵守项目的组件库/样式体系（Tailwind、shadcn、MUI、裸 CSS 皆可）。
- 变体间可共享 `<Header>` 级小件；共享 `<Layout>` 即失效——每个变体要保有推翻布局的自由。
- **只读**：变体接真实数据但不接变更操作；确需写时指向 stub——问题是"该长什么样"，不是"后端通不通"。

## 浮动切换器

底部居中固定条，与页面视觉明确区隔（高对比胶囊 + 阴影），一眼看出不属于被评估的设计：

- `←` **变体键（当前键 + 变体名）** `→`，循环切换。
- 点击经项目路由器更新 `?variant=`（`router.replace` / `navigate` 等）——可分享、可刷新。
- 键盘 `←`/`→` 同步切换；`<input>`、`<textarea>`、`[contenteditable]` 聚焦时不拦截。
- **生产构建隐藏**（`process.env.NODE_ENV !== "production"` 或等价检查）——防原型误合入后切换器见用户。

切换器做成单一共享组件放项目共享 UI 处，两种落位复用。

## 反模式

- 变体只差颜色或文案——那是 tweak，不是原型；真变体在结构上意见相左。
- 变体间共享过多代码——共享布局毁掉分歧。
- 接真实变更操作——只读原型够用，写操作指向 stub。
- 把胜出变体直接提升为生产代码——原型代码是在"无测试、最小错误处理"约束下写的，折叠进真实代码时正经重写。

## 回收

胜出变体折叠进真实代码（A：并入既有页面；B：升格为真路由）；落选变体与切换器从 main 移除，全量去 `prototype/<name>` 分支——留在 main 的变体残骸很快腐烂并误导下一位读者。
