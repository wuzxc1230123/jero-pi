# 架构巡检

回答一个问题：**这个仓库的结构在哪里正在腐化？** 巡检是只读的——产出发现报告，绝不直接重构；发现按不可逆性走既有入口（大改走 SDD 立变更，小改走常规评审轴）。评审透镜看的是每次 diff；本技能看的是仓库本身的长期结构演化，两者正交。

## 巡检轴（按此顺序，逐轴产出发现）

1. **深模块机会（Ousterhout）**：接口大而隐藏少的浅模块——函数被拆得很小但模块接口臃肿，是最常见的伪重构信号；寻找"接口能收缩、实现能加深"的位置。
2. **信息隐藏违反**：跨模块边界泄露的私有知识——别处直接读另一模块的内部数据结构、复制其不变量、或绕过其接口操作其状态。
3. **巨型单元**：相对本仓库既有分布显著超标的文件/模块（以仓库自身常规为基线，不套外部阈值）；先问"为什么长"再问"怎么拆"。
4. **重复与近似重复**：同一逻辑的多个家；与标准库/既有依赖重复的轮子（呼应必要性梯子的前两档）。
5. **命名漂移**：同一概念多个名字——对照 `openspec/specs/glossary/` 共享语言表（存在时）找同义词分叉；词表缺失时先列概念清单，建议用户先补词表。
6. **分层与边界违规**：违反项目自己声明的分层规则（specs/设计文档里的约束优先于本技能的通用直觉）。

## 幂等纪律

- 扫描顺序确定（按轴 → 按路径字典序），同一仓库状态产出同一发现清单（日期除外）——重跑不产生新发现就不是腐化，是抖动。
- 每条发现含：位置（具体路径:行/符号）、症状、**为什么是结构问题而非风格偏好**、建议的 SDD 切入点（候选提案标题）；说不出"为什么"的发现直接丢弃。
- 不给分数、不做排名外的花哨指标——按"改进收益/风险"排序，深模块机会通常收益最高、风险最低。

## 报告与出路

报告以发现清单收尾：前 3–5 条值得立变更的，建议用户走 `/jero-sdd-init` 起提案（标题可直接取自发现）；其余如实列出供下次巡检对比。巡检本身绝不编辑代码、绝不启动子代理执行修复。

## 边界

- 只读：不改代码、不建变更目录、不代替评审透镜或 SDD；
- 发现是散文建议，立项决定归用户；
- 巡检频率由用户掌握（点名或里程碑后邀请）——本技能绝不自我触发、不在每会话自动运行。
