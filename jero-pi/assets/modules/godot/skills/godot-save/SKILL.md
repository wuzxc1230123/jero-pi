# 存档与持久化（Godot 4.x）

管"怎么存才不坏"：存档是最容易写坏的系统。深度知识住模块 references（L2，路径经模块知识入口注入，按需读）。

> **相关技能：** 数据层 Resource 化 → `godot-resources`；纯逻辑可测性 → `godot-gdscript`（static func）；能力数值入档 → 深读 `references/ability-system.md`。

## 何时使用

设计存档结构、写存/读档、做版本迁移、排查损坏或半写丢失时使用；运行中暂存（checkpoint 内存态）不归本技能管。

## 核心要点

- 纪律四件套：**显式版本号 + 原子写（临时文件 + rename）+ 校验和 + 迁移链**（v1→v2→v3 逐级升，不写跳跃迁移）。
- 路径一律 `user://`（跨平台正确）；`res://` 运行时只读，写进去的"存档"是编辑器幻觉。
- 存**数据**不存**节点**：序列化自定义 Resource/字典（ID、数值、位置），绝不经 `var_to_str` 存场景节点引用。
- 结构变更先想迁移：旧档读不进 = 用户资产蒸发；迁移失败要响亮报告，不静默重置。

## 红线

- 直接覆盖写旧档文件（半写/崩溃 = 档没了——原子写是底线）。
- `to_json(var_to_str(node))` 存节点树（版本一变全崩）。
- 无版本号的存档格式（第二版上线那天就是数据事故）。
