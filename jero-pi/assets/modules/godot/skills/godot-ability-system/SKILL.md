# 能力/技能系统（Godot 4.x）

管"技能是数据，施放是流程，效果是对象"。深度知识住模块 references（L2，路径经模块知识入口注入，按需读）。

> **相关技能：** 数值数据层 → `godot-resources`；判定帧与碰撞 → `godot-physics`；与动画单向驱动 → `godot-animation`；联机裁定 → `godot-multiplayer`。

## 何时使用

技能数 ≥ 3 且会成长（加技能只加数据）、做冷却/消耗/buff/状态效果时使用；两个技能的原型直接状态机，别过度设计。

## 核心要点

- 技能定义 Resource 化：`AbilityDefinition`（标签/冷却/消耗/施放时间/效果列表），效果是独立 `AbilityEffect` 子类——加技能加效果 = 加数据加类，不改施放流程。
- 冷却用**单调时钟**（`Time.get_ticks_msec()` 差值 + 每技能一条记录），不用 Timer 节点、不每帧轮询。
- 施放管线固定：检查 → 扣费 → 记冷却 → 前摇 → 判定帧 → 应用效果 → 后摇；判定与效果分离才可重放可测试。
- 标签做互斥/免疫（"沉默禁法术"走标签集合判定），不写技能名硬编码。
- 联机：客户端只发施放请求，冷却/消耗/命中裁定全在权威端。

## 红线

- 冷却/伤害数值写死在按钮或角色脚本（数值进 .tres）。
- Timer 节点管冷却（技能数 × Timer = 场景树垃圾）。
- 动画回调里做裁定/扣费（重复施放温床——裁定只走管线）。
