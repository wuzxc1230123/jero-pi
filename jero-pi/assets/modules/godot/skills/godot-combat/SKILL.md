# 战斗设计（ACT 方法论，Godot 4.x）

管"设计什么、为什么这样设计"：招式集/元规则/Boss 范式/参数基线。深度知识住模块 references（L2，路径经模块知识入口注入，按需读）。

> **相关技能：** 实现层——技能系统数据模型 → `godot-ability-system`；打击感代码（hitstop/震动/反馈层级）→ `godot-game-feel`；Boss AI 行为树 → `godot-game-ai`；受击判定 → `godot-physics`。

## 何时使用

设计角色招式集/连段、Boss 或怪物战斗（范式/阶段/预警）、打击反馈分级目标值、配队与养成效果时使用；技能系统怎么实现、行为树怎么写不归本技能管。

## 核心要点

- **约定先行**：招式集分类/预警语言/受击状态/帧率/命名由项目战斗约定定义，先定约定再设计——不预设任何体系。
- **差异化在"操作动词"层不在数值层**；单角色机制锚点 ≤2；招式 IP 化命名。
- 招式类型手艺：普攻 3–5 段末段最重带位移；蓄力拆 pre/charge/release/recover 且蓄力期不能纯等待；弹反拆 start/success/attack/end。
- 打击感有参数基线（5 攻击类型 × hitstop/震动/VFX 层数/泛白目标值），设计时定档、实现时落地。
- Boss：16 范式选型（A 型 HP 阶段化起步），每阶段教一个机制，转换触发三分（血线/韧性/玩家行为）。
- 配队：一个 win condition + 三角色围绕；Driver + Sub-DPS + Support×2 最稳；脱手是灵魂。

## 红线

- 抄别项目体系当通用规则（九招招式集/红光必闪是他人选择）。
- 单一机制收益过高 / 全屏无躲位 AOE / telegraph 模糊逼背板。
- 大招长且不可打断、蓄力期无操作、召唤物强过玩家。
