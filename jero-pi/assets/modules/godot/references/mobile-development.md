# 移动端开发（Mobile / Android / iOS）

移动端不是"桌面版缩小"：输入面（触屏）、性能量级（移动 GPU/发热）、
生命周期（后台/中断）、发布链（商店审核）四个维度都是另一套纪律。
桌面原型先跑通可以，但**发布决策必须移动端真机说了算**。

## 输入面

- 触屏事件：`InputEventScreenTouch`（按下/抬起）+ `InputEventScreenDrag`
  （拖动）；多点触控按 `index` 区分手指。
- 虚拟摇杆/按钮：自绘 `Control`（`ui-theming.md`）+ 上面两个事件实现；
  按住判定用矩形含点，别用鼠标事件模拟（会有合成鼠标双触发问题）。
- 系统返回键（Android）：项目设置里把返回键映射成 `ui_cancel` 动作，
  逻辑层只认动作（`input-actions.md` 的铁律在移动端同样成立）。
- 触屏 UI 尺寸：点击目标 ≥ 44pt 级别；手指精度 ≠ 鼠标，桌面调好的
  按钮在手机上可能点不中。

## 性能量级（先预算后开发）

- 移动 GPU 与桌面差一个量级：后处理是第一杀手（`shaders-visuals.md`
  移动档）、粒子数/光源数/透明过载是前三坑；预算表按移动端定，
  桌面性能只是红利。
- 发热与耗电：满帧跑满负载 = 降频降亮度恶性循环；提供 30/60fps 档位。
- 内存：系统随时回收后台；纹理与音频预算钉死，加载策略分批。

## 适配与安全区

- 拉伸模式 `canvas_items` + 基准分辨率 + `expanding`（`ui-theming.md`）；
  纵横比碎片化（打孔屏/刘海/折叠屏）用 `DisplayServer.get_display_safe_area()`
  收边，UI 不钉绝对角。
- 横竖屏锁定在导出预设里钉死，别运行时横跳。

## 生命周期（与桌面最大的行为差）

- `NOTIFICATION_APPLICATION_PAUSED` / `_RESUMED` / `_FOCUS_OUT`：
  **退后台即存档**（半写防护见 `save-systems.md`）——移动系统随时杀
  后台进程，"下次启动恢复"是基本要求不是加分。
- 来电/通知打断：音频总线暂停恢复、计时器暂停语义要显式处理。

## 发布链

- Android：APK/AAB + keystore 签名（密钥丢失=更新线断裂，备份纪律
  严肃对待）；权限最小化（导出预设里逐项勾，别全开）。
- iOS：证书/描述文件链 + 审核；真机调试配 Xcode 工具链。
- **真机验证红线**：模拟器/编辑器通过 ≠ 真机通过（性能、触控、签名、
  商店规则四处都会翻车）——发布前真机全流程过一遍并留证
  （`verification.md` 语义）。

## NEVER

- **NEVER 只在桌面/模拟器验证就发布移动端**——四个维度全是坑。
- **NEVER 忽略 PAUSED 通知**：后台被杀没存档 = 一星差评直通车。
- **NEVER 桌面级性能假设**（满屏透明粒子/多光源/后处理叠加）——
  移动端预算先行，砍效果在立项时砍，不在发布前砍。
- **NEVER 鼠标事件模拟触屏**（合成事件双触发）；走 ScreenTouch/Drag。
