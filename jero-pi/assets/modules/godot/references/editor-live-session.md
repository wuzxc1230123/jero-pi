# 编辑器活会话：何时用、何时不该用

"活会话"指与**正在运行的 Godot 编辑器**保持双向连接（经 MCP 服务器或
编辑器插件）实时读写场景树。它解决的是交互编辑问题，**不是**验证手段。

## 分工边界（先记住这个，再选工具）

| 需求 | 用什么 | 为什么 |
| --- | --- | --- |
| 构建/校验/测试/取证 | headless CLI（verification.md） | 退出码可回归、CI 可跑、无人值守 |
| 搭场景、调节点、高频往返试错 | 编辑器活会话（MCP/插件桥） | 进程内存里的状态，CLI 探不进 |
| 截一张编辑器视口图 | 临时编辑器插件桥（装→截→拆） | 活会话的最小子集，不留常驻 |

**判断口诀：结论要能从退出码与文件还原的，一律 CLI；要伸进编辑器
进程内存的，才是活会话。**

## 活会话方案现状（2026-10）

- **godot-ai**（hi-godot/godot-ai，MIT，免费；v4 面向 Godot 4.7+）：attach 链
  MCP 客户端 → `godot-ai attach`（stdio）→ 本地服务（127.0.0.1:8000，鉴权
  HTTP，Python 侧需 `uv`/uvx）→ 编辑器插件（环回 WebSocket :9500）。46 工具/
  120+ 操作：场景创建/编辑、节点检视修改、GDScript 写入即解析校验+热重载、
  信号接线、UI 配置、材质/动画/粒子/相机/环境、项目资产检索（如
  PackedScene）、编辑器内跑场景测试套件；C# 仅文本写入、无构建/报错回传
  （attach C# 需 .NET 版编辑器）。两跳凭证独立轮换、无未认证回退；工具全量
  见其 docs/TOOLS.md。对 Pi 系客户端：`/jero:install-module godot` 会把
  `godot-ai` 档自动并入 `~/.pi/agent/mcp.json`（幂等、同名用户档不覆盖；
  声明≠安装——uvx/uv 与编辑器插件仍需自装）。
- **Godot MCP Pro**（专有，$15）：同类架构，163 工具，收费。
- **自建插件桥**：往项目暂存一个 EditorPlugin（写入 `project.godot`
  的 `[editor_plugins]` 启用项）→ 启动编辑器握手截屏 → **拆除干净**。
  适合一次性取证；纪律是绝不留下 Autoload/插件残骸。

## 安全纪律（接入任何活会话前逐条确认）

- 连接必须**仅环回**（127.0.0.1）；确认方案有认证/凭证轮换，无未认证
  回退——裸 WebSocket 本地端口会被同机进程访问。
- 活会话是**开发期工具**，不进 CI、不进发布流程；`.mcp.json`/编辑器
  插件配置不入库（gitignore），防他人环境被动接入。
- 经活会话做的修改最终要落成磁盘上的场景/脚本变更并过验证三道门
  （verification.md）——"编辑器里看着对了"不算证据。
- 断线重连/心跳是方案自身能力，别自己造轮子；会话内未保存状态在
  连接断开时的丢失语义要提前知道（编辑器侧仍是权威存储）。

## NEVER

- **绝不用活会话做回归验证**——依赖"编辑器开着"的验证在 CI 里必死；
  回归结论必须 headless CLI 产出。
- **绝不让代理经活会话绕过项目文件直接改运行态**而不落盘：会话结束
  即蒸发，且与 git 历史脱钩，评审无从核查。
- **绝不对生产/他人项目开远程活会话**；桥接别的机器走 SSH 且显式
  授权，默认拒绝。
- 装了编辑器插件（godot-ai 或自制桥）后，`project.godot` 与
  `addons/` 的差异要留意提交卫生——别把开发期插件提交进仓库主干。
