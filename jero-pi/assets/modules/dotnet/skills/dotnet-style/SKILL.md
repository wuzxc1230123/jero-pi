# 风格核心（C#/.NET）

管"代码是写给人读的"这条底线：清晰 > 简洁 > 可维护 > 一致，冲突时前者胜。工具管的归工具（`dotnet format`），结构归人。

> **相关技能：** 命名决策 → `dotnet-naming`；语言特性选型 → `dotnet-language`；验证格式纪律 → `dotnet-tester`。

## 何时使用

写或改 C# 代码时作为底线惯例；评审可读性、决定要不要抽方法/降嵌套时使用。格式归 `dotnet format`，本技能管结构决策。

## 核心要点

- **格式归工具**：`dotnet format --verify-no-changes` 过 CI，格式争论零容忍；`.editorconfig` 是格式与命名的单一事实源。
- **优先级序**：清晰 > 简洁；"聪明"的代码（嵌套三元、隐式转换技巧、重载选型要靠规范推演）默认重写为显然。
- **guard clause 早返回**：参数校验/边界条件先处理后返回，主路径不缩进；嵌套超过 2–3 层是抽方法信号。
- **表达式体成员**：单行逻辑用 `=>`；方法体超 3 行回块体——不为一行省略牺牲可断点性。
- **`var` 的取舍**：右侧类型显然（`new Dictionary<string, int>()`）用 `var`；类型名是信息（接口选择、工厂返回）写显式类型。
- 注释解释"为什么"，不复述代码"做什么"；XML doc 只写公共 API 面。

## 红线

- 与 `dotnet format` 输出不一致的手工格式（包括"顺手"的空行调整）。
- 为省行数牺牲可读性（单行多语句、压掉异常分支）。
- 死代码/被注释掉的代码块留存——删除即干净，git 记得一切。
