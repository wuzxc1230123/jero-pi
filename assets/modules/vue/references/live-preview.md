## 接线与前置

```jsonc
// 项目 .pi/mcp.json——/jero:install-module vue 时自动并入（幂等三律：
// 内容一致跳过/同名用户档保留/畸形保命不动）
{ "mcpServers": { "playwright": { "command": "npx", "args": ["@playwright/mcp@0.0.83"] } } }
```

- **首用信任确认**：Pi ≥0.99 项目作用域 MCP 档第一次连接前需要用户确认——确认一次后常驻，`/jero:doctor` 可显影在档/缺席/用户改动三态。
- **浏览器前置（一次性）**：`npx playwright install chromium`——MCP 服务器由 npx 即起，浏览器二进制是另一层（声明≠安装工具链，与 godot 束的 uvx 前置同纪律）；Linux 无头环境加 `--with-deps` 装系统库。
- **参数面（按需手改用户档）**：`--headless`（无头默认关——视觉验证要看真窗口；服务器环境开）、`--browser <chromium|firefox|webkit>`（默认 chromium）、`--viewport-size`、`--isolated`（干净 profile）。包内束声明保持最小（npx + 钉版），定制是个人的。

## 视觉验证工作流

```
npm run dev（端口钉住，如 VITE_DEV_PORT=5173）
  → 导航 http://localhost:5173
  → 截图基线（整页 + 关键区域元素级）
  → 改代码（热更新生效）
  → 再截图对比 → 迭代到位 → 关 server
```

- **迭代纪律**：每轮改动截一次同名文件（`shot-01.png` 递增），对比看差异；会话结束前留证（截图路径写进变更说明）。
- **交互路径**：表单走真实流（填入 → 点提交 → 看结果态与错误态两分支）；路由跳转后等网络空闲再截（避免骨架态当结论）。
- **可访问性快照**：断言结构/文案用 a11y 树（文本形态、可 diff、省 token）——像素截图看视觉，快照看语义，两层互补。
- **响应式矩阵**：375/768/1280 三档视口各一截；暗色/亮色主题两侧各一截（主题是高频回归面）。

## 与开发面的配合

- **dev server**：vite/nuxt dev 起在钉住端口（团队约定进 `.env`，避免每次换端口）；代理后端走 `server.proxy`（vite-toolchain）——页面在浏览器里连的就是真实开发拓扑。
- **组件隔离预览**：Storybook/Histoire 谱系的项目可用其渲染路由做组件级截图（比整页更窄的验证面）；无则用临时路由挂载目标组件。
- **Console/网络面**：浏览器 console 错误与失败请求是视觉之外的硬信号——截图"看着对"但 console 红了一片不算过。

## 降级与边界

- MCP 面不可用（宿主 <0.99 / 未信任确认 / 浏览器未装）：照常交付，变更说明明示"未做视觉验证，请人工过一眼"——绝不编造"我看过"。
- **视觉验证不替代验证协议**：`vue-tsc`/build/`vitest run` 三道门是唯一退出码证据（verification-gates）；截图回答"看起来对不对"，不回答"测试过没过"。
- **安全边界**：视觉验证只打本地 dev server 或只读页面——生产域名上的提交/删除/支付类操作绝不自动点按。

## 红线

- 未截图声称页面正常；截图当退出码证据。
- 生产环境自动执行写操作。
- 把浏览器会话当持久状态（每轮验证后关 server，端口与进程不留垃圾）。
