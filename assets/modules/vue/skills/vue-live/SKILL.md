# 浏览器活会话（vue-live）

前端开发的代理之眼：Playwright MCP（微软官方，`@playwright/mcp`）把真实浏览器接进会话——代理能导航、截图、点按、填表、读可访问性树，改完代码立刻看渲染结果，不再盲改。

> **相关技能：** dev server 与工具链 → `vue-tooling`；视觉验证不替代三道门 → `vue-testing`；性能测量另有面板 → `vue-performance`。

## 何时使用

迭代页面视觉（布局/样式/交互）、验证"用户实际看到什么"、排查只在真浏览器复现的问题时使用。

## 核心要点

- **接线（随束自动）**：本束声明的 playwright MCP 档在 `/jero:install-module vue` 时幂等并入项目 `.pi/mcp.json`——Pi ≥0.99 项目作用域，**首用有项目信任确认**（确认一次后常驻）。
- **前置（一次性，声明≠装工具链）**：浏览器二进制需自装——`npx playwright install chromium`（缺它 MCP 服务器能起但浏览器打不开，报错信息自带指引）；无头环境加 `--with-deps`。
- **工作流**：起 `npm run dev`（vite/nuxt，端口进 `.env` 钉住）→ 导航到本地地址 → 截图看基线 → 改代码 → 再截图对比迭代；交互路径用点按/填表走真实流（表单→提交→结果态）。
- **工具面**：导航/截图（整页与元素级）/点按/填输入/读可访问性快照（比像素截图更适合断言结构）/多标签页；用法与参数谱系见 `references/live-preview.md`。
- **响应式与主题**：断点验证切视口尺寸（手机/平板/桌面各截一张）；暗色模式切换后补截图（`useDark` 类主题的两侧都要看）。
- **降级**：MCP 面/浏览器不可用时照常交付——代码审查 + 明确告知"未做视觉验证，请人工过一眼"；绝不编造"我看过页面了"。

## 红线

- 未真截图却声称页面正常（编造视觉证据）。
- 把截图当验证结论——视觉验证是辅助，退出码三道门仍是唯一验证证据。
- 在生产域名上自动点按提交/删除类操作（视觉验证只打本地 dev server 或只读页面）。
